# Архитектура

В общих чертах, как устроен проект и почему так. Здесь только решения уровня всего проекта: структура, слои, общие приёмы, правила для всех компонентов. Решение записывается в той же задаче, где принято. Разделов под отдельный компонент и деталей реализации нет — неочевидное решение внутри компонента объясняется комментарием рядом с кодом, история и отвергнутые варианты — в описании PR. Решение устарело — пункт исправляется, а не дописывается рядом.

## Структура

```
src/
  app/                    роутинг (App Router): layout, page, metadata
    <route>/_components/  секции, нужные только этой странице: папка на компонент, как в ui-kit
  ui-kit/                 UI-кит: папка на компонент — button/{index.tsx, index.test.tsx}
  widgets/                виджеты: каркасы и крупные области страниц со слотами, элементы уровня layout — sidebar-layout/, cursor/
  styles/
    globals.css           подключение Tailwind, базовые стили; импортируется в app/layout.tsx
    theme.css             дизайн-токены в @theme
  constants/              контент-данные: проекты, контакты, адреса страниц
  lib/                    утилиты и чистые функции, image-loader.ts
  assets/                 исходники картинок для статического импорта в next/image
scripts/                  скрипты сборки (optimize-images.ts — адаптер next build)
docs/                     гайды по отдельным темам (список — в AGENTS.md, «Документация»)
public/                   только файлы с постоянным внешним URL, если иначе нельзя (см. images.md)
```

Папки создаются, когда в них появляется первый файл, не заранее.

## Слои

- `src/app/` — только роутинг и сборка страниц из компонентов. Папка `src/pages` запрещена: Next считает её Pages Router. Секции одной страницы — в `<route>/_components/` (папки с `_` Next исключает из роутинга); компонент нужен на двух и больше страницах — переносится в `ui-kit/`, каркас или крупная область страницы — в `widgets/`. Максимальная ширина контента и боковые отступы сайта задаются один раз в `app/layout.tsx`, обёртка `box-content`: отступы добавляются снаружи максимальной ширины, а не вычитаются из неё. Сетку с боковой колонкой (главная, кейс) задаёт виджет `SidebarLayout`: и боковую колонку, и колонку контента — страница только наполняет слоты.
- `src/ui-kit/` — переиспользуемые компоненты без знания о страницах и контенте: всё приходит через пропсы.
- `src/widgets/` — виджеты: каркасы и крупные области страниц со слотами (`SidebarLayout` — `main` с левой колонкой). Как и кит, ничего не знают о контенте. Граница с китом — по роли: элемент, даже собранный из других компонентов (`ProjectCard` поверх `Card`), остаётся в ките; область, в которую ставят другие компоненты, — виджет. Виджет — и элемент уровня layout: один на весь сайт, подключается в `app/layout.tsx`, слотов у него нет (`Cursor` — точка-курсор поверх всех страниц). Это не элемент кита, и ни к одной странице он не относится. Разделение по составу, как в shadcn (`ui` — примитивы, `components` — композиции), не выбрано: там каркас `Sidebar` считается примитивом.
- `src/constants/` — контент-данные (проекты, контакты, тексты), типизированный TS: `next/image` требует статический импорт картинок, поэтому не JSON. Текст с разметкой (абзацы, выделение, списки) — JSX прямо в данных (`.tsx`, тип `ReactNode`) голыми тегами без классов: стили тегам задаёт компонент, который этот текст выводит. Из кита данные берут только то, что оформляет сам текст (`Emoji`), и типы вариантов (`SectionLabelAccent`). Разметка данные рендерит, а не копипастит. Адреса страниц — только из `routes` (`src/constants/routes.ts`): `href={routes.project(slug)}`, не строка руками; новая страница — сначала адрес в `routes`. `src/lib/` — общие чистые функции, нужные в двух и больше местах. Логика из компонентов выносится в чистые функции, чтобы её можно было тестировать; пока функция нужна одному компоненту, она лежит в его папке (`utils.ts`), а не в `src/lib/`.
- `src/styles/` — токены (`theme.css`) и базовые стили. `src/assets/` — исходники картинок.
- Server Components по умолчанию. `"use client"` — только где нужны state, эффекты, браузерные API или анимации; client-граница как можно ниже по дереву.
- Интерактивность без состояния (hover, раскрытие) делается на CSS, а не клиентским компонентом.

## Компоненты: структура

Каждый компонент — в `ui-kit/`, `widgets/` и `<route>/_components/` — в своей папке с именем компонента в kebab-case. Сам компонент — `index.tsx`, тест — `index.test.tsx` рядом:

```
src/ui-kit/
  button/
    index.tsx         компонент (named export)
    index.test.tsx    тест
src/app/_components/
  projects-carousel/
    index.tsx
    index.test.tsx
    utils.ts          чистые функции, нужные только этому компоненту
    utils.test.ts
```

- Импорт снаружи — через папку: `import { Button } from "@/ui-kit/button"`.
- Компоненты кита импортируют друг друга так же, через папку: `ContentCard` берёт `Card` из `@/ui-kit/card`.
- Тест импортирует компонент из своей папки: `import { Button } from "."`.
- Чистые функции компонента лежат в его папке: одна — файл `utils.ts`, несколько — папка `utils/`. Функция нужна в двух и больше местах — переносится в `src/lib/`.

### Почему без barrel-файлов

Ultracite включает правило Biome `performance/noBarrelFile`: импорт из файла-реэкспорта заставляет сборщик, dev-сервер и Vitest загрузить все модули, которые он реэкспортирует, а не только нужный. Ещё barrel легко даёт циклические импорты (компонент кита импортирует соседа из общего `index.ts`, который импортирует сам этот компонент — в рантайме `undefined`) и уводит «Go to definition» в `index.ts`. Подробно: [Speeding up the JavaScript ecosystem, part 7](https://marvinh.dev/blog/speeding-up-javascript-ecosystem-part-7/).

Поэтому реэкспортов нет совсем: компонент сам лежит в `index.tsx` своей папки, импорт через папку работает без них, и `noBarrelFile` действует во всём коде.

## UI-кит: приёмы

- **Поверхность отдельно от содержимого.** `Card` — подложка: фон, радиус, обрезка и общая раскладка. Отступы и размер задаёт тот, кто её использует; карточки с содержимым собираются поверх `Card`.
- **Обводка фокуса — одна на весь сайт**, базовым стилем `:focus-visible` в `globals.css`. Компоненты её не повторяют, обводка повторяет `rounded-*` элемента.
- **`className` — последним, через `cx`** из `class-variance-authority`. `cx` только склеивает строки и не разрешает конфликты классов Tailwind (`tailwind-merge` не подключён): переопределять снаружи утилиту, которая уже задана внутри (`aspect-*`, `p-*`), нельзя — результат зависит от порядка в CSS.
- **Варианты — через `cva`.** `buttonVariants({ variant })` отдаёт строку классов. Ссылка, которая выглядит как кнопка, — это `<a>`/`<Link>` с `className={buttonVariants(...)}`, а не `<Button>` с `href`.
- **Картинка — одним пропом** `{ src: StaticImageData; alt: string }`. Как выбирать `sizes` и `loading` — [images.md](images.md).

# Архитектура

Как устроен код и почему так. Сюда записываются решения и находки, которые всплыли по ходу работы: что выбрали, от чего отказались и по какой причине. Новое решение — новый пункт в нужном разделе, устаревшее — исправить, а не дописать рядом.

## Слои

- `src/app/` — только роутинг и сборка страниц из компонентов. Секции одной страницы — в `<route>/_components/`.
- `src/ui-kit/` — переиспользуемые компоненты без знания о страницах и контенте: всё приходит через пропсы.
- `src/lib/` — контент-данные (проекты, ссылки) и чистые функции. Логика из компонентов выносится сюда, чтобы её можно было тестировать.
- `src/styles/` — токены (`theme.css`) и базовые стили. `src/assets/` — исходники картинок.
- Всё — Server Components. В UI-ките пока нет ни одного `"use client"`: интерактивность (hover, раскрытие описания) сделана на CSS.

## UI-кит: структура

Каждый компонент — в своей папке с именем компонента в kebab-case:

```
src/ui-kit/
  button/
    button.tsx        компонент (named export)
    button.test.tsx   тест
    index.ts          публичный вход: export { Button, buttonVariants } from "./button";
  card/
    …
```

- Импорт снаружи — через папку: `import { Button } from "@/ui-kit/button"`. Внутрь папки (`@/ui-kit/button/button`) снаружи не импортировать.
- Компоненты кита импортируют друг друга так же, через папку: `ContentCard` берёт `Card` из `@/ui-kit/card`.
- Тест импортирует соседний файл (`./button`), не `index.ts`.
- `index.ts` — только named-реэкспорт того, что нужно снаружи. Без `export *` и без логики, тестов у него нет.
- Общего `src/ui-kit/index.ts` нет — сознательно, см. ниже.

### Почему без корневого barrel-файла

Ultracite включает правило Biome `performance/noBarrelFile`: импорт из файла-реэкспорта заставляет сборщик, dev-сервер и Vitest загрузить все модули, которые он реэкспортирует, а не только нужный. Ещё barrel легко даёт циклические импорты (компонент кита импортирует соседа из общего `index.ts`, который импортирует сам этот компонент — в рантайме `undefined`) и уводит «Go to definition» в `index.ts`. Подробно: [Speeding up the JavaScript ecosystem, part 7](https://marvinh.dev/blog/speeding-up-javascript-ecosystem-part-7/).

Решение: общего barrel нет, а `index.ts` в папке компонента реэкспортирует только этот компонент — он загружает один модуль, проблем выше не создаёт. Для таких файлов правило выключено точечно, в `biome.json` (`overrides` → `src/ui-kit/*/index.ts`). В остальном коде `noBarrelFile` действует.

## UI-кит: приёмы

- **Поверхность отдельно от содержимого.** `Card` — подложка: фон, радиус, `overflow-hidden` и общая раскладка карточек — колонка, где первый блок (тег) прижат к верху, последний (текст) к низу (`flex flex-col justify-between`). Отступы и размер задаёт тот, кто её использует. `ContentCard` и `ProjectCard` собираются поверх `Card`.
- **Обводка фокуса — одна на весь сайт**, базовым стилем `:focus-visible` в `globals.css` (`outline-2 outline-border-focus outline-offset-2`). Компоненты её не повторяют, обводка повторяет `rounded-*` элемента. Раньше классы `focus-visible:outline-*` копировались в каждый компонент, а обычные ссылки в тексте получали браузерную обводку вместо токена. У `Card` была ещё `has-focus-visible:` — осталась от растянутой ссылки и ни разу не срабатывала, убрана.
- **`className` — последним, через `cx`** из `class-variance-authority`. `cx` только склеивает строки и не разрешает конфликты классов Tailwind (`tailwind-merge` не подключён): переопределять снаружи утилиту, которая уже задана внутри (`aspect-*`, `p-*`), нельзя — результат зависит от порядка в CSS.
- **Варианты — через `cva`.** `buttonVariants({ variant })` отдаёт строку классов. Ссылка, которая выглядит как кнопка, — это `<a>`/`<Link>` с `className={buttonVariants(...)}`, а не `<Button>` с `href`. У `Button` по умолчанию `type="button"`.

## Карточка-ссылка (`ProjectCard`)

- Ссылка — вся карточка: `<Link>` оборачивает `Card`. Растянутую ссылку на заголовке (`after:absolute after:inset-0`) пробовали и отказались — кликабельной должна быть карточка целиком.
- Без доп. атрибутов доступное имя ссылки собралось бы из всего содержимого (alt обложки, тег, заголовок, описание). Поэтому `aria-labelledby` указывает на заголовок, `aria-describedby` — на описание. Id — через `useId()`: он работает и в Server Components.
- Обводка фокуса — общая, на самой ссылке; `rounded-2xl` у ссылки — чтобы обводка повторяла углы карточки.
- Описание и градиент на `lg` скрыты и появляются по `group-hover:` / `group-focus-visible:`.
- Описание на `lg` плавно выезжает снизу (300 мс, только при `motion-safe`): обёртка анимирует `grid-rows-[0fr] → grid-rows-[1fr]`, внутри `overflow-hidden`, у самого текста — `translate-y-full → 0` и `opacity`. Высоту текста знать не нужно. Свёрнутое описание остаётся в дереве доступности (нулевая высота и `opacity` его не прячут). Раньше было `sr-only` ↔ `not-sr-only` — так анимировать нельзя.
  - Почему arbitrary `grid-rows-[0fr]`/`[1fr]`, а не встроенный `grid-rows-1`: тот — `repeat(1, minmax(0, 1fr))`, другой тип трека, и переход от `0fr` к нему идёт скачком. Значения используются один раз — в токены `theme.css` не выносятся (исключение из запрета arbitrary values, см. AGENTS.md, «Правила кода»). Отвергнуто: `max-height` (нужно угадывать высоту), `interpolate-size` (только Chromium), JS/`motion` (хватает CSS).
- Градиент под текстом — слой `before:` с `opacity`: `background-image` не анимируется, поэтому `bg-none ↔ bg-linear-to-t` переключался бы скачком.
- Обложка внутри карточки лежит под тегом и текстом за счёт `isolate` на карточке и `-z-10` у блока картинки. Слой градиента (`before:` с `-z-10`) идёт в DOM после картинки, поэтому рисуется над ней, но под текстом.

## Картинки в компонентах

- Картинка передаётся одним пропом: `image: { src: StaticImageData; alt: string }`.
- `sizes` — по ширине компонента в сетке. У `ProjectCard` зашито `(min-width: 1280px) 390px, (min-width: 1024px) 33vw, (min-width: 640px) 50vw, 100vw` под сетку 1/2/3 колонки в `max-w-7xl`: шире 1280 контейнер перестаёт расти и карточка остаётся ≈389px, а без верхней ступени `33vw` на 1920 заставлял качать вариант в 1,6 раза шире. Другая сетка — добавить проп `sizes`.
- Картинки первого экрана грузятся сразу: проп `eager` у `ProjectCard` ставит `loading="eager"`. На главной он у всего первого ряда (`index < 3`): на десктопе в ряду три карточки, и LCP-элементом становится любая из них — какая, зависит от ширины экрана и пропорций обложки. Отдать `eager` только первой карточке не вышло: на 1440 Next предупреждал про LCP у второй и третьей.
- `fetchPriority="high"` у `ProjectCard` не ставится: по [images.md](images.md) он только у одной картинки, а в ряду карточек заранее неизвестно, какая из них LCP. Он для одиночной hero-картинки.
- Пайплайн и типовые случаи — [images.md](images.md).

## Известные мелочи

- Chrome пишет в Issues «Lazy-loaded images should have explicit dimensions» для обложек `ProjectCard`: классы `h-auto w-auto` перебивают атрибуты `width`/`height`. Это информационное сообщение, не ошибка: картинка лежит в абсолютно позиционированном блоке и сдвига вёрстки нет.
